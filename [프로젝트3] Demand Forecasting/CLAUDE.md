이 파일은 이 저장소에서 **분석 보고서를 쓰거나 고칠 때** Claude가 따르는 규칙이다.
보고서의 내용(숫자·결론)은 여기 적지 않는다. 내용은 항상 저장소의 보고서 원고와 결과 파일에서 읽는다.

## 0. 프로젝트 설정값 (프로젝트가 바뀌면 이 블록만 고친다)

| 항목 | 값 |
|---|---|
| 분량 | **부록 포함 13쪽 이내** (A4 기준). 최종 쪽수는 PDF로 확인한다 |
| 최종 형식 | **PDF**(제출·공유용) + **Word(.docx)**(팀이 직접 고치는 용도) + 마크다운 원고. Google Docs는 .docx 파일을 가져와 연다 (Google Drive·Docs 커넥터는 이 환경에 없다) |
| 그림 | **실제 그림을 본문에 넣는다.** 자리 표시로 두지 않는다. 원본 사진을 그대로 쓰지 않고, 같은 데이터로 본문 폭에 맞게 다시 그린다 (9절 참고) |
| 표 | 메시지를 증명하는 핵심 열만 남긴다. 긴 표는 부록으로 보낸다. **단, 과제 가이드가 그 표에 요구한 열은 절대 줄이지 않는다** (7절 「가이드 지정 열」 참고) |
| 과제 요구 문서 | 저장소의 과제 가이드·채점 기준 문서 (필수 항목·순서·루브릭의 기준) |
| 메인 질문의 출처 | 보고서 원고 첫 줄의 주제·핵심 질문. Claude가 임의로 바꾸지 않는다 |
| 언어·문체 | 한국어, 본문은 「~다」체 |
| 확정 문장 | 확정된 운영 규칙 문장은 사용자가 승인한 그대로 쓴다. 「(가안)」 같은 표시를 붙이지 않는다 |
| 출력 파일 이름 | `최종보고서_n` (PDF, .docx, .md 모두 같은 n). n은 출력 폴더(`report/`)에 있는 `최종보고서_*.pdf` 중 가장 큰 번호 + 1이고, 없으면 1이다. 이전 번호 파일은 덮어쓰지 않는다 |
| 원고 | 출력 폴더(`report/`)의 원고를 쓴다. 원고가 없으면 어떤 파일을 쓸지 먼저 묻는다. 원고는 고치지 않는다. 결과는 항상 `최종보고서_n`으로 낸다. 원고 이름이 `최종보고서_초안.md`에서 바뀌면 그때 사용자에게 확인한다. 다음 요청부터는 가장 큰 번호의 `최종보고서_n.md`를 원고로 쓴다(원고가 없을 때만 묻는다) |
| 출력 횟수 | **번호는 요청 1번당 1개다.** 한 요청 안에서 여러 단계를 고쳐도 마지막에 한 번만 만든다. 중간 확인용 출력은 `작업중_미리보기.pdf` 하나만 덮어쓴다(번호 없음). 확인을 기다리느라 멈출 때는 `최종보고서_n`을 만들지 않는다 |

## 1. 독자: 일반인과 전문가가 함께 읽는다

- **일반인**(의사결정자): 요약과 각 섹션 첫 문장만 읽어도 결론과 해야 할 행동을 알 수 있어야 한다.
- **전문가**(채점자·검토자): 본문의 근거와 부록·재현 조건으로 숫자를 검증할 수 있어야 한다.
- 그래서 정보는 **층**으로 쌓는다. 결론은 맨 위에 두고, 근거는 본문에, 세부 설정·긴 표·파일 경로는 부록에 둔다.
- 납득은 "더 많은 정보"가 아니라 **"질문 → 답 → 근거"의 끊기지 않는 연결**에서 나온다.

## 2. 줄기: 메인 질문 하나를 잡고 끝까지 설득한다 (피라미드 원칙)

보고서 전체는 하나의 피라미드다.

```
메인 질문
   └─ 답 (한 문장 — 숫자·단위·행동 포함)
        ├─ 근거 1 ─ 데이터·표·그림
        ├─ 근거 2 ─ 데이터·표·그림
        └─ 근거 3 ─ 데이터·표·그림
```

1. **메인 질문은 하나다.** 보고서의 모든 섹션은 이 질문의 답을 세우거나, 그 답을 얼마나 믿을 수 있는지 보여 주는 데 쓰인다.
2. **답을 먼저 쓴다.** 보고서 첫 쪽에 답이 있어야 한다. 독자가 결론을 찾아 읽게 만들지 않는다.
3. **근거는 3개 안팎, 서로 겹치지 않고 빠짐없이(MECE).** 대표적인 틀은 다음과 같다(내용에 맞게 고른다).
   - 「무엇이 일어나는가(크기) → 그것을 반영하면 무엇이 나아지는가(효과) → 어디까지 믿을 수 있는가(한계·민감도)」
   - 「문제가 있다 → 원인은 이것이다 → 이렇게 고친다」
4. **도입은 SCQA로 짧게.** 상황(Situation) → 문제(Complication) → 질문(Question) → 답(Answer)을 3∼5문장 안에 담는다.
5. **과제가 섹션 순서를 정해 두었으면 그 순서를 지킨다.** 피라미드는 순서를 바꾸는 게 아니라, 정해진 각 섹션이 메인 질문의 어느 근거를 맡는지 정해서 꿰는 방식으로 적용한다.

### 줄기 점검 질문 (문단마다)

- 이 문단은 메인 질문의 답을 **세우는가, 검증하는가, 한계를 보여 주는가?**
- 셋 다 아니면 → 부록으로 보내거나 지운다.

## 3. 맥킨지식 작성 규칙

### 3-1. 제목은 문장으로 (액션 타이틀)

- **적용 범위를 구분한다.**
  - **번호 섹션 제목(① 권고 요약 ∼ ⑥ 추가 발견과 다음 할 일, 부록 A1∼A4)** 은 과제가 정한 이름이므로 그대로 둔다.
  - 그 아래의 **소제목(###)·표 제목·그림 캡션**은 모두 결론 문장으로 쓴다. 과제가 섹션 이름을 정했다고 해서 소제목까지 이름표로 두지 않는다.
  - 번호 섹션의 결론은 섹션 첫 문장(굵게)으로 쓴다(3-2).
  - 예: 「비용과 절감액」 → 「절감 6.40억 원 중 4.74억 원은 모형에서 나왔다」, 「인력이 가장 많이 모자란 10건」 → 「부족 상위 10건 중 7건이 추석 연휴 후반이다」 (숫자는 항상 결과 파일로 확인한 뒤 쓴다)
- 소제목·표·그림 제목은 **그 부분의 결론을 담은 한 문장**으로 쓴다.
  - 나쁜 예: 「후보 모형 비교」, 「비용 분석」
  - 좋은 예: 「달력 정보를 넣은 모형이 비용을 가장 많이 줄였다」
- **제목만 이어 읽어도 이야기가 완성되어야 한다**(수평 논리). 제목 아래 내용은 그 제목을 증명해야 한다(수직 논리).
- 제목의 주장은 데이터로 확인한 뒤에 쓴다. 숫자로 확인되지 않은 제목은 쓰지 않는다.

### 3-2. 섹션 첫 문장 = 결론

- 각 섹션은 결론 문장으로 시작하고, 그다음에 근거를 쓴다.
- 결론 문장에는 가능하면 **숫자 + 단위 + 비교 대상**을 넣는다. 예: "기존 방식보다 비용이 ○억 원(○%) 줄었다"

### 3-3. 숫자마다 "So what?"

- 숫자를 쓴 뒤에는 그 숫자가 독자(의사결정자)에게 뜻하는 바를 한 문장으로 붙인다.
- 비교 기준 없이 숫자만 두지 않는다(기존 방식 대비, 목표 대비, 다른 집단 대비 등).

### 3-4. 표·그림은 메시지 하나

- 표·그림 하나에는 메시지 하나만 담는다. 두 가지를 말하고 싶으면 나눈다.
- 구성
  - **표**: 표 위에 소제목 또는 굵은 한 줄로 메시지 문장 → 표 → 필요하면 「주:」 한 줄
  - **그림**: 그림 → 그림 바로 아래 **캡션 한 줄(메시지 문장)** → 필요하면 같은 줄이나 다음 줄에 「주:」. 캡션 규칙은 9절을 따른다
- 본문 표는 메시지를 증명하는 데 필요한 행·열만 남긴다. 전체 표는 부록에 두고 본문에 "부록 ○ 참고"라고 적는다. **과제 가이드가 요구한 열은 예외로 반드시 남긴다**(7절).
- 강조(굵게)는 표마다 핵심 값 1∼2개에만 쓴다.

## 4. 덜 산만하게: 무엇을 본문에 두고 무엇을 뺄 것인가

| 본문에 둔다 | 부록으로 보낸다 | 지운다 |
|---|---|---|
| 메인 질문의 답을 세우는 표·그림 | 전체 비교표, 개소·항목별 긴 표 | 메인 질문과 연결되지 않는 발견(→ 「추가 발견」 섹션에 1∼2개만) |
| 선택의 이유를 한 문장으로 | 선택지마다의 상세 비교, 의사결정 기록 | 분석 과정의 시간순 서술("먼저 ~했고 다음에 ~했다") |
| 핵심 지표 1개 + 결정 기준 | 보조 지표의 정의와 역할 설명 | 같은 숫자의 반복 |
| 재현에 필요한 최소 조건 | 하이퍼파라미터·환경·파일 경로 | 결론에 영향 없는 시도 |

- **방법 설명은 결과보다 짧게** 쓴다.
- 지표 선정·전처리처럼 하고 싶은 말이 많은 부분일수록 **"왜 이걸 골랐나" 한 문장 + 근거 숫자 하나**로 줄이고, 나머지는 부록으로 보낸다.
- 한 문단에 숫자는 3개 이하로 쓴다. 더 필요하면 표로 만든다.
- 같은 결론을 두 곳에서 증명하지 않는다. 한 곳에서 증명하고 다른 곳에서는 참조한다.

## 5. 두 독자를 위한 용어·숫자 규칙

- 전문용어는 **처음 나올 때 괄호로 쉬운 말 한 줄**을 붙인다. 예: WAPE(전체 실제값 대비 오차 합의 비율)
- 같은 개념은 끝까지 같은 단어로 부른다(동의어를 섞지 않는다).
- 약어·내부 코드명(변수명, 파일명, 모형 별칭)은 본문에 쓰지 않는다. 필요하면 부록 재현 조건에만 쓴다.
- 숫자는 단위를 통일하고(예: 금액은 억 원 소수 둘째 자리), 의사결정에 필요한 정밀도까지만 쓴다.
- **가운뎃점(·) 규칙**: 가운뎃점을 남발하지 않는다.
  - 문장 안에서 두 개를 나열할 때는 「와/과」 또는 「및」으로 쓴다. (예: 날짜·개소 → 날짜와 개소)
  - 세 개 이상을 나열할 때는 쉼표로 쓴다. (예: 궁·종묘·왕릉 → 궁, 종묘, 왕릉)
  - 표 머리글이나 짧은 라벨에서 대비·묶음은 슬래시(/)나 쉼표로 쓴다. (예: 모자란·남는 인원 → 모자란/남는 인원)
  - 숫자 나열은 쉼표로 쓴다. (예: 231·215·215·222명 → 231, 215, 215, 222명)
  - 범위는 물결표(∼)로 쓴다. (예: 2·3주 전 → 2∼3주 전)
  - 가운뎃점을 남기는 곳은 굳어진 표현(「명·일」, 「개소·일」, 제목의 「궁·능」)과 공식 명칭(모형 이름 「Chronos-2 + 공휴일·무료 개방」)뿐이다.
  - 바꾼 뒤에는 문장을 읽어 어색한지 확인하고, 캡션과 표 안의 글자도 같은 기준으로 맞춘다.
- 수식은 본문에서 최소화한다. 꼭 필요하면 문장 속에서는 유니코드 기호(τ, Cᵤ 등)로 쓰고, 독립 수식은 한 줄로 따로 둔다.
- 용어가 5개를 넘으면 부록에 용어집을 둔다.

## 6. 분량 관리 (부록 포함 13쪽)

- 쓰기 전에 **쪽 예산**을 섹션별로 먼저 정하고 사용자에게 확인받는다. 기본 배분은 다음과 같다.
  - 요약: 1쪽 (요약 본문 기준, 과제가 요구하는 권고표는 별도로 셈)
  - 본론 섹션: 전체의 약 60∼70%
  - 부록: 3쪽 이하
- 어림 기준: A4 한 쪽 ≈ 한글 본문 1,500자, 또는 표 25행 안팎. **그림은 본문 폭에 맞춰 높이 약 60mm 이하**(약 1/4쪽).
- 예산을 넘으면 **4절의 표 순서대로** 줄인다(본문 → 부록 → 삭제). 채점·필수 항목은 줄이지 않는다.
- **빈 공간을 줄인다.** 그림이나 표가 쪽 끝에서 잘리거나 다음 쪽으로 밀려 빈 공간이 크게 남으면, 그림 높이·표 행 수를 조정해 다시 맞춘다. 최종 쪽 배치는 PDF 결과로 확인한다.

## 7. 채점 안전장치: 줄이다가 필수 항목을 빠뜨리지 않는다

- 작업을 시작할 때 과제 가이드의 **필수 항목·요구사항·루브릭**을 읽고, 아래 형식의 대조표를 만들어 사용자에게 보여 준다.

| 요구 항목 | 보고서 위치(섹션·표·문장) | 상태 |
|---|---|---|
| (가이드의 항목) | ② 첫 문장 / 표 2 | 충족 · 부분 · 없음 |

- 보고서를 고칠 때마다 이 대조표로 다시 확인하고, 빠진 항목이 생기면 바로 알린다.
- 덜 산만하게 만드는 것보다 **필수 항목 충족이 우선**이다. 필수 항목은 부록으로 보내더라도 본문에서 위치를 한 줄로 가리킨다.
- 가이드가 요구한 **자주 하는 실수·개소 유형별 지표·가정 목록·예측 단위와 모형 선택지·무료 제외 비교표·왕릉 개소별 권고**는 빠지면 안 되는 항목이다. 줄이는 과정에서 이 항목들을 지우지 않는다.

### 가이드 지정 열 (표를 줄일 때도 지우지 않는다)

표의 열을 줄이거나 표를 다시 만들 때, 아래 열은 반드시 남긴다. 고친 뒤에는 이 목록과 표를 한 줄씩 대조한다.

| 표 | 반드시 있어야 하는 열 | 근거 |
|---|---|---|
| 인력이 가장 많이 모자란 10건 | 날짜 · 개소 · **실제 관람객** · **예측값(0.8 분위수)** · 모자란 인원 · 원인(한 문장) | 가이드 요구사항 7 「실제 관람객, 예측값, 원인을 한 문장씩 표로」 |
| 자주 하는 실수 | 실수 · **측정한 크기(숫자)** · 막은 방법 | 가이드 「자주 하는 실수」 — 크기를 숫자로 측정하고 막은 방법을 쓴다 |

| FVA 표 | 더한 정보 · 1순위 지표 · 비용(원) · 앞 행 대비 | 요구사항 6 |

## 8. 숫자와 사실의 정확성

- 모든 숫자는 저장소의 결과 파일·원고에서 가져온다. 숫자를 지어내지 않는다.
- **「계산 안 함」·「검증 필요」로 표시하기 전에 반드시 아래 순서로 찾는다.** 한 곳이라도 값이 있으면 그 값을 쓰고, 어디서 찾았는지 사용자에게 알린다.
  1. 결과 파일(`data/`, `appendix/report_addons/`, `appendix/run_o1/`, `outputs/` 등)
  2. **이전 원고**(`report/report.md`, `report/검토_무료개방일과_피처정의.md`, `report/AI_CONTEXT.md`, `report/제언_가안.md`, 이전 버전 보고서)
  3. 노트북 실행 결과(`notebooks/*.ipynb` 출력 셀)
- 세 곳 모두에 없을 때만 「계산 안 함 (검증 필요)」로 표시하고, **그 즉시 사용자에게 "○○ 값을 찾지 못했다"고 알린다.** 조용히 표시만 하고 넘어가지 않는다.
- **이미 숫자가 있던 칸을 「계산 안 함」으로 바꾸지 않는다.** 값이 의심되면 바꾸기 전에 사용자에게 먼저 묻는다.
  - 이 프로젝트 예: 자주 하는 실수 1번(휴관일 0)은 이전 원고에 측정값이 있다 — 직전 7일 평균 WAPE 0 포함 0.600 vs 개방일만 0.480, 경복궁 50.2% vs 36.7%(가이드 값 재현). 결과 파일로 확인해 넣는다.
- 숫자를 고치거나 새로 쓸 때는 작업 메모(사용자에게 하는 답)에서 출처 파일을 밝힌다. 본문에는 파일 경로를 쓰지 않는다(부록 재현 조건은 예외).
- 외부 사실(공지·보도 등)은 출처 링크를 함께 적는다.
- 같은 숫자가 여러 곳에 나오면 모두 같은 값인지 확인한다. **다른 단위·다른 기준으로 잰 값은 기준을 함께 적는다**(예: 포함률 59%는 일 단위, 0.734는 주 단위).
- 값이 맞지 않으면 바로 알린다. 고쳤다면 무엇을 왜 고쳤는지 함께 적는다.
- 노트북의 측정 셀(예: `paid == 0` 비교)은 **측정 전용**이다. 측정 결과를 예측에 쓰는 무료 개방일 기준으로 쓰지 않는다. 무료 개방일은 항상 달력 규칙으로 정한다.
- **작업 중 원고**에서는 미완·결정 필요 항목을 지우지 말고 눈에 띄게 표시해 둔다(예: `⬜ [미완]`).
- **제출본(PDF·.docx)에는 미완 표시가 하나도 남으면 안 된다.** 제출본을 만들기 전에 미완 항목마다 아래 중 하나로 처리한다.
  - 해결했으면 → 본문에 반영하고 표시를 지운다.
  - 해결하지 못했지만 알릴 가치가 있으면 → 「⑤ 한계」 또는 「⑥ 다음 할 일」에 평범한 문장으로 옮긴다(예: "2026-01-01 무료 여부는 공지로 확인하지 못했다").
  - 의미가 없으면 → 지운다.
  - 「미완 항목」이라는 소제목, `⬜`·체크박스 기호, 「(가안)」 표시는 제출본에 남기지 않는다.
- 어떤 미완 항목을 어떻게 처리했는지 사용자에게 목록으로 알린다.

## 9. 파일 형식·그림·표 호환 규칙

- 마크다운은 단순하게 쓴다: 제목은 H1∼H3까지만, 표는 병합 셀·중첩 표 없이, HTML 태그는 쓰지 않는다.
- **그림은 실제로 넣는다.** 자리 표시(`[그림 n] …`)로 두지 않는다.
  - 원본 그래프 사진은 크기가 작아 글씨가 안 보이거나, 키우면 빈 공간이 생긴다. 그래서 같은 데이터로 **본문 폭(약 170mm)에 맞게 다시 그린 PNG**를 쓴다. 높이는 6절과 같이 약 60mm 이하.
  - 그림 파일은 보고서 폴더의 `figs/`에 두고, 원본 사진 파일은 그대로 둔다.
- **그림 캡션은 한 번만 쓴다.**
  - 그림 바로 아래에 메시지 문장 한 줄만 쓴다. 그림과 캡션은 쪽이 갈리지 않게 묶는다.
  - **그림 이미지 안에는 제목을 넣지 않는다**(다시 그릴 때 `plt.title`·`suptitle` 없이 그린다).
  - 마크다운 이미지의 대체 텍스트(`![여기]`)는 비워 두거나 짧은 파일 설명만 쓴다. 변환기가 대체 텍스트를 기울임꼴 「그림: …」 줄로 한 번 더 찍기 때문이다. 캡션 문장을 대체 텍스트와 본문에 동시에 쓰지 않는다.
  - PDF를 만든 뒤, 그림마다 같은 문장이 두 번 이상 보이지 않는지 확인한다.
- **표 규칙**
  - 표 앞뒤에는 빈 줄을 둔다. 빈 줄이 없으면 표가 글자로 찍힌다.
  - 머리글 줄은 한 번만 쓴다. 표를 고칠 때 옛 머리글이 남지 않았는지 확인한다.
  - 열 너비를 고정하지 않는다. 내용에 맞게 늘어나도록 두어 불필요한 빈 칸을 줄인다.
- 물결표 범위(1∼4)는 `∼`(U+223C)로 쓴다(일부 편집기에서 `~`가 취소선이 됨).
- 각주 대신 표·그림 아래 「주:」 한 줄을 쓴다.
- **산출물 세트**: 요청 작업이 모두 끝나면 PDF, .docx, .md 세 파일을 한 번에 `최종보고서_n`으로 만든다. 만든 뒤 세 파일이 모두 있는지 경로로 확인한다(파일이 사라진 적이 있었다).
- **파일 이름**: 세 파일은 모두 `최종보고서_n`으로 짓는다(0절 「출력 파일 이름」). 이전 번호의 파일은 그대로 두고 새 번호를 쓴다.

## 10. 작업 순서

1. **읽기**: 과제 가이드·루브릭 → 보고서 원고 → 결과 파일·프로젝트 맥락 문서.
2. **스토리라인 먼저**: 본문을 쓰기 전에 아래만 뽑아 사용자에게 확인받는다.
   - 메인 질문 / 답 한 문장 / 근거 3개
   - 섹션별 액션 타이틀(결론 문장)과 각 섹션이 맡는 근거
   - 섹션별 쪽 예산
   - 필수 항목 대조표(7절)
3. **섹션 쓰기**: 확인받은 스토리라인대로 쓴다. 섹션별 변경은 글로 보고하고, 파일 출력은 마지막에 한 번만 한다.
4. **점검**(매번):
   - [ ] 소제목(###)·표 제목·그림 캡션이 모두 결론 문장인가 (이름표로 남은 것이 없는가. 번호 섹션 제목은 예외)
   - [ ] 제목만 읽어도 이야기가 이어지는가
   - [ ] 모든 문단이 메인 질문에 연결되는가(2절 점검 질문)
   - [ ] 섹션 첫 문장이 결론인가, 숫자·단위·비교 대상이 있는가
   - [ ] 전문용어 첫 등장에 쉬운 설명이 있는가
   - [ ] 쪽 예산 안인가(PDF 기준 13쪽 이내)
   - [ ] 필수 항목 대조표가 모두 충족인가
   - [ ] 「가이드 지정 열」(7절)이 표마다 모두 있는가 — 특히 모자란 10건의 실제 관람객·예측값
   - [ ] 「계산 안 함」 칸이 있다면 8절 순서(결과 파일 → 이전 원고 → 노트북)로 찾아봤고, 사용자에게 알렸는가
   - [ ] 제출본에 미완 표시(`⬜`, 「미완 항목」, 「(가안)」)가 남아 있지 않은가
   - [ ] 그림마다 캡션이 한 번만 보이는가 (그림 안 제목·「그림:」 줄 중복 없음)
   - [ ] 모든 숫자에 출처 파일이 있는가
   - [ ] 표가 글자로 깨지지 않고, 그림이 실제로 보이는가
   - [ ] PDF·.docx·.md 세 파일이 모두 만들어졌고 경로에 존재하는가
5. **큰 구조 변경**(섹션 이동, 표 삭제, 결론 문장 변경)은 고치기 전에 제안하고 확인받는다.

## 11. 사용자 요청 반영 기록 (2026-10-15 ∼ 10-16)

사용자가 직접 요청한 수정 사항이다. 앞으로 같은 실수를 반복하지 않도록 지킨다.

1. **형식**: 최종은 PDF. 사용자가 직접 고칠 수 있도록 .docx도 함께 준다. 링크는 실제 파일 경로로 준다.
2. **구성 승인**: 스토리라인과 쪽 예산(요약 1 · 본문 약 7 · 권고표 1 · 부록 3)을 확인받은 뒤에 본문을 쓴다.
3. **운영 규칙 문장**: 사용자가 승인한 문장을 그대로 쓴다. 「(가안)」 표시를 붙이지 않는다.
4. **그림**: 자리 표시가 아니라 실제 그림을 넣는다. 그림이 작거나 쪽 끝에서 잘리지 않게, 본문 폭에 맞춘 다시 그린 그림을 쓴다.
5. **빈 공간**: 그림·표 때문에 쪽 사이에 빈 공간이 크게 남지 않게 조정한다.
6. **표**: 핵심 열만 남긴다. 단, 가이드가 요구한 열(7절 「가이드 지정 열」)은 지우지 않는다. 표가 글자로 깨지지 않는지 확인한다.
7. **빠진 항목**: 자주 하는 실수, 개소 유형별 지표, 가정 목록, 예측 단위·모형 선택지, 무료 제외 비교표, 왕릉 개소별 권고는 반드시 포함한다.
8. **검증되지 않은 숫자**: 결과 파일 → 이전 원고 → 노트북 순서로 찾아본 뒤에도 없을 때만 「계산 안 함 (검증 필요)」로 표시하고 바로 알린다. 이미 있던 숫자를 「계산 안 함」으로 바꾸지 않는다(8절).
9. **불일치 보고**: 숫자가 다르면 바로 알리고, 기준(일 단위·주 단위 등)을 함께 적는다.
10. **노트북**: `paid == 0` 비교는 측정용이다. 무료 개방일 기준으로 쓰지 않는다.
11. **파일 확인**: 산출물을 만든 뒤 파일이 실제로 있는지 확인하고 알린다.
12. **응답 방식**: 한국어로 짧게 답한다. 모르는 것은 "확인하지 못했다"고 쓴다.
13. **미완 표시**: 제출본에는 「미완 항목」 박스·`⬜`·「(가안)」을 남기지 않는다. 한계나 다음 할 일로 옮기거나 지운다(8절).
14. **캡션 중복 금지**: 그림 설명은 그림 아래 한 줄만. 그림 안 제목과 대체 텍스트로 같은 문장을 반복하지 않는다(9절).
15. **소제목은 결론 문장**: ①∼⑥ 번호 섹션 제목만 과제 이름 그대로 두고, 그 아래 소제목·표 제목·그림 캡션은 결론 문장으로 쓴다(3-1).
16. **가운뎃점 정리**: 문장 안 나열의 가운뎃점은 쉼표나 「와/과」로 바꾼다. 범위는 ∼로 쓴다(5절). 모형 이름과 「명·일」 같은 굳어진 표현만 남긴다.
17. **파일 이름**: 출력은 `최종보고서_n`으로 짓고, 이전 번호 파일은 덮어쓰지 않는다(0절).
18. **1/28 권고 같은 숫자 변경**: 권고 숫자를 바꾸는 수정은 계산 결과를 먼저 보여 주고 사용자가 승인한 뒤에만 반영한다.
19. **작업 전 점검**: 0절, 5절, 9절, 10절에 규칙이 반쯤만 들어갔을 수 있으니 작업 전에 이 네 곳을 읽고 빠진 규칙을 채운다.
20. **출력 횟수**: 번호는 요청 1번당 1개다. 중간 확인은 `작업중_미리보기.pdf` 하나만 덮어쓴다(0절).
