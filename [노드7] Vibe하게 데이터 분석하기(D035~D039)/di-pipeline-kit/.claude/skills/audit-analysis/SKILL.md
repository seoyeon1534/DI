# /audit-analysis — 분석 감사

## 이 스킬이 하는 일

의견을 내지 않는다. **다시 계산한다.**

`queries/`의 스크립트를 재실행해 저장된 `.out`과 대조하고,
문서에 적힌 수치가 그 출력과 같은지 확인한다.

`@report`가 대시보드를 채점하지 않는 이유가 이것이다 — 같은 파이프라인의
마지막 단계가 상류를 채점하면 요약하려는 동기가 흠을 찾으려는 동기를 이긴다.
분석 감사는 단계 밖에 있어야 한다.

## 작업

### 1. 재계산

```bash
RUN="${1:-runs/latest}"
cd "$RUN"
for f in queries/*.py; do
  [ -f "$f" ] || continue
  python3 "$f" > "/tmp/$(basename "$f" .py).new" 2>&1
done
```

각 스크립트의 새 출력을 저장된 `.out`과 비교한다.

| 결과 | 뜻 |
|---|---|
| 동일 | 재현됨 |
| 다름 | **재현 실패** — 데이터가 바뀌었거나 스크립트가 결정적이지 않다 |
| 실행 실패 | 스크립트가 깨졌다. 그 수치는 검증 불가 |

### 2. 문서 대조

**`02` · `03` · `04` · `05` 네 문서를 모두 본다.** 04·05만 보면 상류에서 만들어진
오류가 통과한다. 문서에만 있고 스크립트에 없는 수치를 찾는다.

**출처 없는 수치가 이 검증의 핵심 발견이다.** 틀린 수치보다 흔하다.

### 3. 같은 것이 문서마다 몇 개인가 — 표류 점검

문서를 넘어가며 **같은 이름의 수치가 다른 값으로 적힌 곳**을 찾는다.
값 하나하나가 각자의 `.out`에서 재현되더라도, 이름이 같고 값이 다르면 그것이 결함이다.

표로 만든다. 이름이 같은 항목만 모으면 눈에 보인다.

```markdown
| 이름 | 02 | 03 | 04 | 05 | 06·07 | 판정 |
|---|---|---|---|---|---|---|
| 저매출·고반품 상품 수 | 42 | 42 | 53 | 39 | 39 | 표류 — 정의 3종 |
| 파레토 80% 상품 수 | 602 | 602 | 620 | 604 | 604 | 표류 |
| 전체 매출 | £1,016,574 | — | 두 값 병기 | £1,192,531 | £1,192,531 | 표류 |
```

**하류가 상류 값을 조용히 바꾼 곳을 특히 찾는다.** 상류가 "둘 다 50%" 라고 했는데
하류가 "4.3%" 로 적었으면, 하류가 맞더라도 **상류가 안 고쳐진 채 남아 있다.**
그 상류 문서를 근거로 쓴 판단이 전부 그 값 위에 서 있다.

### 4. 표본 타당성 — 재현되지만 틀린 수치를 찾는다

**이 점검이 없으면 검증은 재현성만 본다. 재현되는 계산이 타당한 계산은 아니다.**

원본 데이터를 직접 읽어 스크립트를 하나 쓰고 `queries/`에 저장한다.

```
audit_sample_integrity.py
```

세 가지를 센다.

| 점검 | 무엇을 세는가 | 걸리면 |
|---|---|---|
| 분자 > 분모 | 반품 수량 > 판매 수량인 항목 수 | 원 거래가 표본 밖. 비율 계산 불가 |
| 분모 = 0 | 반품만 있고 판매가 없는 항목 수 | 반품률 100% 는 값이 아님 |
| n 임계값 | 순위표·권고 목록 항목 중 n<30, n<5 개수 | analysis-principles.md 위반 |

그리고 **그 항목들이 문서의 순위표·권고 목록에 실제로 몇 개 올라가 있는지** 센다.
올라가 있으면 그 표의 결론은 표본이 만든 신호다.

```markdown
| 문서 | 표 | 전체 | 표본 결손 | n<30 | 판정 |
|---|---|---|---|---|---|
| 02 | 반품률 Top 10 | 10 | **10** | 8 | 표 전체가 표본 결손 |
| 05 | 정리 권고 | 39 | 7 | 26 | 권고 근거 재검토 필요 |
```

### 5. 규칙 위반 점검

`.claude/rules/` 기준으로 기계적으로 확인할 수 있는 것만 본다.

| 점검 | 근거 |
|---|---|
| 지표에 네 요소(이름·계산식·단위·제외조건)가 다 있는가 | metric-definition.md |
| "속일 수 있는 경우" 가 비어 있지 않은가 | metric-definition.md |
| 인사이트에 "이 결론이 틀렸다면" 이 채워져 있는가 | analysis-principles.md |
| 비율에 표본 크기(n)가 병기되어 있는가 | analysis-principles.md |
| n<30 그룹이 순위표에 올라 있지 않은가 | analysis-principles.md |
| n<5 값이 마스킹되어 있는가 | analysis-principles.md |
| 집계 단위가 명시되어 있는가 | analysis-principles.md |
| 한 표 안에 다른 필터의 수치가 섞여 있지 않은가 | analysis-principles.md |
| 인접한 수치가 서로 모순되지 않는가 (고유값 수 > 행 수 등) | analysis-principles.md |
| 필터 전후 행 수의 뺄셈이 맞는가 | analysis-principles.md |
| 마크다운 표의 헤더 열 수와 구분선 열 수가 같은가 | 형식 |
| 제외했다고 선언한 항목이 뒤에서 다시 인용되지 않는가 | 형식 |
| 상류 문서를 인용한 숫자가 그 문서에 실제로 있는가 | analysis-principles.md |
| 지표 이름에 집계 단위가 들어 있는가 | metric-definition.md |

**네 문서(`02`·`03`·`04`·`05`) 전부에 적용한다.** 04·05만 보면
순위표 규칙 위반은 대개 02에 있으므로 놓친다.

### 6. 대시보드 점검 — 파일을 실제로 읽는다

`06_dashboard.html`을 **Read로 읽는다.** 경로 확인만 하지 않는다.
판정마다 **근거(해당 클래스명·줄 위치)** 를 적는다. 근거를 못 적으면 판정하지 않는다.

| 점검 | 확인 방법 |
|---|---|
| 플레이스홀더가 남아 있지 않은가 | `>—<` 개수 |
| 04에 없는 지표가 있지 않은가 | KPI 카드 레이블 대조 |
| 계열 2개 이상인 차트에 범례가 있는가 | 범례 요소 존재 |
| 이중 축이 없는가 | y축 요소 개수 |
| 단위·제외조건이 화면에 있는가 | 메타 영역 텍스트 |
| 빈 탭이 없는가 | 패널별 내용 유무 |

### 7. 저장

`runs/latest/outputs/analysis_audit_report.md`

## 출력 형식

```markdown
# 분석 감사 리포트

## 판정
재현 성공 N / 재현 실패 N / 실행 실패 N / 출처 없는 수치 N
표류 N / 표본 결손 N / 규칙 위반 N

재현과 타당성을 **따로** 적는다. 재현이 다 통과해도 타당성이 실패할 수 있다.

## 재계산 결과
| 스크립트 | 저장된 값 | 재계산 값 | 결과 |

## 출처 없는 수치
| 문서 | 위치 | 수치 | 비고 |

## 표류 — 같은 이름, 다른 값
| 이름 | 02 | 03 | 04 | 05 | 06·07 | 판정 |

## 표본 타당성
| 점검 | 개수 | 문서의 순위표·권고에 올라간 수 | 판정 |

## 규칙 위반
| 점검 | 결과 | 위치 | 근거 |

## 대시보드
| 점검 | 결과 | 근거(클래스·줄) |

## 조치 권고
- [어느 단계를 다시 실행해야 하는가. 전체 재실행은 권고하지 않는다]
```

## 원칙

- **의견을 내지 않는다.** 재계산 결과와 규칙 위반만 보고한다
- **재현성과 타당성을 구분해서 보고한다.** "재현 11/11 통과" 와
  "이 표는 표본 결손 위에 서 있다" 는 동시에 참일 수 있다.
  재현이 통과했다는 이유로 **"결론에 영향을 주는 오류 없음" 이라고 쓰지 않는다**
- 근거를 적을 수 없는 항목은 판정하지 않는다. 빈 판정보다 미판정이 낫다
- 통과 항목도 적는다. 무엇을 확인했는지 보이지 않으면 검증이 아니다
- 조치는 단계 단위로 권고한다. 전체 재실행을 권하지 않는다

## 하지 않을 것

- 산출물 내용을 직접 수정하는 것 — 보고만 한다
- "잘 만들어졌습니다" 같은 총평
- 파일을 읽지 않고 판정하는 것
- 04·05만 보고 02·03을 건너뛰는 것
- 재현이 통과했다는 이유로 타당성 점검을 생략하는 것
