# @analysis

## 목적

숫자를 읽는 것이 아니라 **변화의 의미를 해석한다.**
그리고 그 해석이 틀렸을 때 어디서 드러날지를 함께 적는다.

## 인풋

1. `runs/latest/outputs/03_problem_definition.md` — 답해야 할 질문과 앞둔 결정
2. `runs/latest/outputs/04_kpi_summary.md` — **지표 정의와 제외조건**
3. `runs/latest/input/00_context.md` — 이미 아는 것 / 이미 시도한 것 / 제약
4. `runs/latest/input/` 원본 데이터

`00_context.md` 의 "이미 아는 것" 을 발견으로 다시 보고하지 않는다.
사람이 이미 아는 것을 인사이트로 내놓는 것이 이 단계의 가장 흔한 실패다.

## 작업

### 1. 방법론 선택

각 분석 질문마다 방법론을 고르고 **이유를 적는다.**

| 질문 유형 | 방법론 |
|---|---|
| 전체적으로 어떤 상태인가 | 기술통계 + 지표 현황 |
| X가 Y에 영향을 주는가 | 상관 / 회귀 |
| 어떤 그룹이 다른가 | 세그먼트 비교 (각 그룹 n 병기) |
| A가 B보다 나은가 | 군 간 비교 — 표본 수 확인 필수 |
| 추세가 바뀌었는가 | 시계열 / 변화점 |
| 무엇이 전체에 기여하나 | 파레토 / 기여도 분해 |
| 행동 패턴이 있는가 | 코호트 / RFM / 세그먼트 |

**제외조건을 04에서 그대로 가져와 적용한다.** 임의로 바꾸지 않는다.
바꿔야 한다고 판단되면 그 사실을 보고하고 `@metrics` 재실행을 권한다 — 직접 고치지 않는다.

### 2. 계산 — 스크립트로 남긴다

```
runs/latest/queries/05_<무엇을계산했나>.py
runs/latest/queries/05_<무엇을계산했나>.out
```

문서의 모든 수치는 `.out` 에서 온다. 스크립트 없이 적은 값은 "추정" 으로 표시한다.
출력에 실행 시각·타임스탬프를 넣지 않는다.

**상류 문서의 수치를 인용할 때는 그 문서에서 그대로 옮긴다.** 다시 계산해서 적지 않는다.
`04` 가 "상위 10개 29.60%" 라고 했으면 29.60% 를 쓴다. 내가 계산해 26.4% 가 나왔으면
그것은 인용이 아니라 새 계산이고, **둘을 나란히 적고 왜 다른지 밝혀야 한다.**

### 2-1. 순위표와 권고 목록에 표본 결손 필터를 적용한다

`04_kpi_summary.md` 의 제외조건에 적힌 **표본 결손 항목을 목록에서 먼저 뺀다.**
n<30 만 걸러내고 표본 결손을 안 걸러내는 것이 가장 흔한 누락이다.

```
1) 04 의 제외조건에서 표본 결손 목록을 읽는다
2) 표본 결손 · n<30 · n<5 를 목록에서 뺀다
3) 남은 것만 정렬한다
4) 표 아래에 적는다 — "표본 결손 제외 N개 · n<30 제외 M개"
```

**표가 한 행만 남았다면 그 한 행을 의심한다.** 걸러낸 뒤에 하나만 남는 표는
대개 그 하나도 걸러져야 할 항목이다.

### 3. General → Specific

순서를 지킨다. 세부부터 시작하지 않는다.

1. 전체 현황 — 핵심 지표의 현재 상태
2. 주요 분해 — 가장 영향력 있는 차원으로 나눠 비교
3. 원인 탐색 — 차이가 큰 그룹의 세부 원인
4. 이상 발견 — 예상과 다른 패턴, 경고 신호
5. 기회 발견 — 개선 여지, 긍정적 예외

### 4. 인사이트

3개 이내. 각각 아래를 채운다.

```markdown
### 인사이트 N: [제목]
- **발견:** 무엇이 보이는가
- **근거:** [수치] ← queries/05_xxx.out
- **왜 중요한가:** 앞둔 결정에 어떻게 영향을 주는가
- **한계:** 표본 크기, 인과 미확인 등
- **이 결론이 틀렸다면:**
  - 반증 조건: [무엇이 관찰되면 이 결론이 무너지는가]
  - 확인 방법: [지금 데이터로 가능한가 / 무엇이 더 필요한가]
  - 대안 설명: [같은 데이터를 설명하는 다른 가설 1개]
```

**"이 결론이 틀렸다면" 을 비워 두지 않는다.**
채울 수 없으면 그 인사이트는 아직 인사이트가 아니다.

### 5. 액션

- **P1 즉시** — 바로 시작할 수 있는 것
- **P2 2~4주** — 준비·검증이 필요한 것
- **P3 모니터링** — 지켜볼 지표 / 기준값 / 주기

`00_context.md` 의 제약에 걸리는 액션은 넣지 않거나 제약을 명시한다.

### 6. 저장

`runs/latest/outputs/05_analysis_report.md`

## 출력 형식

```markdown
# 05. 분석 보고서

## 분석 경로 요약
(General → Specific 한 줄)

## 방법론 선택 근거
| 질문 | 방법론 | 선택 이유 |

## 핵심 인사이트 (3개 이내)
### 인사이트 1 … (발견 / 근거 / 왜 중요한가 / 한계 / 이 결론이 틀렸다면)

## 대시보드용 한 줄 메시지
"[의사결정자가 보자마자 이해할 한 문장]"

## 전체 현황 (General)
## 세부 분석 (Specific)
## 추천 액션
P1 / P2 / P3

## 계산 스크립트
| 무엇 | 스크립트 | 출력 |

## 해석 주의사항
- 인과와 상관의 구분
- 표본 부족으로 신뢰성이 낮은 결과
- 추가 데이터가 있으면 더 정확해질 부분
```

## 원칙

- 절대 변화와 상대 변화를 구분한다
- 추측은 추측이라고 밝힌다 — "…로 보인다" 와 "…이다"
- 인사이트는 앞둔 결정으로 이어져야 한다
- General → Specific 흐름을 지킨다
- 지표를 재정의하지 않는다
- 사람이 이미 아는 것을 발견으로 내놓지 않는다

## 하지 않을 것

- 지표 정의·제외조건 변경 (보고하고 `@metrics` 재실행 권고)
- 차트·HTML 생성 (`@dashboard` 의 일)
- 반증 칸을 비우거나 형식적으로 채우는 것
