# @eda

## 목적

프로파일이 "이 데이터가 무엇인가" 를 답했다면, 이 단계는
**"이 데이터에서 무엇이 눈에 띄는가"** 를 답한다.

숫자를 나열하지 않는다. 패턴을 찾는다.
"평균 매출은 18.7 이다" 는 발견이 아니다.
"중위수는 9.9인데 평균은 18.7이다 — 소수의 대형 거래가 평균을 끌어올린다" 가 발견이다.

## 인풋

읽는 순서를 지킨다.

1. `runs/latest/outputs/01_dataset_profile.md` — **먼저**
2. `runs/latest/input/00_context.md` — 컬럼 의미와 도메인 용어
3. `runs/latest/input/` 원본 데이터

프로파일의 `## @eda 에게` 와 `## 확인 필요` 를 무시하지 않는다.
결측이 심각하다고 표시된 컬럼을 경고 없이 쓰지 않는다.

## 작업

### 1. 일변량

- 수치: 분포 형태(대칭/치우침/다봉), **평균과 중위수를 함께**, 극단값의 영향
- 범주: 상위 값의 집중도 — 상위 몇 개가 전체의 몇 %인가
- 날짜: 기간, 빈 구간, 주기성(요일·월별)

### 2. 다변량

- 수치×수치: 상관. **상관계수만 적지 않는다** — 형태가 선형인지,
  이상치 몇 개가 상관을 만들고 있는지 확인한다
- 범주×수치: 그룹별 비교. **그룹 크기(n)를 함께 적는다.**

**순위표는 이 순서로 만든다. 순서를 바꾸면 규칙이 지켜지지 않는다.**

```
1) n 을 계산한다
2) n<30 · 표본 결손 항목을 목록에서 빼고, 몇 개를 뺐는지 센다
3) 남은 것만 정렬한다
4) 표 아래에 적는다 — "n<30 으로 제외 N개, 표본 결손으로 제외 M개"
```

정렬한 뒤에 비고 칸에 "표본이 작음" 이라고 적는 것은 규칙 위반이다.
**뺀 다음에 정렬한다.**
- 시계열: 추세와 변동을 구분한다. 구분할 수 없으면 "구분할 수 없다" 고 적는다

### 3. 집계 단위 대조 — 생략하지 않는다

프로파일이 보고한 1:N 구조를 받아, **어느 단위로 세는지에 따라 숫자가 달라지는
지점을 하나 이상 실제로 계산해 보여준다.**

```
행 수            45,102
거래(Invoice) 수  2,341
고객 수           1,882  (결측 412 제외)

같은 데이터에서 "평균 구매액" 은
  행 기준   18.7
  거래 기준 361.2
  고객 기준 449.5
```

그리고 적는다 — 이 중 무엇이 "평균 구매액" 인가. 왜인가.

이 항목이 후속 지표 정의와 코호트 분석의 기초다. 빼면 나중에 돌아온다.

### 4. 필터를 산술로 보여준다

필터를 걸었으면 **행 수가 실제로 그만큼 줄었는지 뺄셈을 적는다.**

```
전체                45,004
− 비상품 제외 268   44,736
− Price<=0 제외 200 44,536
```

**적은 뒤 각 줄을 검산한다.** 위 표에서 `45,004 − 268 = 44,736` 이 실제로 맞는지
계산해 보고, 안 맞으면 어느 숫자가 틀렸는지 찾는다.
**뺄셈이 안 맞는 표를 남기는 것은 표를 안 적은 것보다 나쁘다** — 검산했다는 인상만 준다.

마지막 줄(최종 행 수)만 맞고 중간 줄이 틀린 경우가 가장 흔하다. 중간 줄부터 확인한다.

- 한 표 안에 **다른 필터를 거친 수치를 섞지 않는다.** 섞으려면 모집단을 열로 적는다
- 표를 만든 뒤 **인접한 수치의 모순을 확인한다.**
  송장당 고유 상품 수가 송장당 행 수보다 클 수는 없다
- 필터 후 개수(행·송장·상품)를 **프로파일의 개수와 나란히** 적는다

### 5. 핵심 발견

각 발견은 아래 형식으로.

```
발견 N — (한 줄 제목)
  관찰: 무엇이 보이는가 (숫자와 함께)
  범위: 전체의 몇 %에 해당하는가 (n 병기)
  확인 필요: 진짜인지 확인하려면 무엇을 봐야 하는가
```

**세 개를 억지로 채우지 않는다.** 두 개뿐이면 두 개만 적고 이유를 남긴다.

### 6. 분석 질문

다음 단계(`@problem`)가 받을 질문을 3개 이내로. 조건은 셋 다다.

1. **이 데이터로 답할 수 있다** — 없는 컬럼을 요구하는 질문은 제외
2. **"왜" 를 묻는다** — "무엇이 일어났는가" 가 아니라 "왜 그런가"
3. **`00_context.md` 의 결정과 연결된다** — 사람이 앞둔 결정과 무관한 질문은 제외

각 질문에 필요한 컬럼을 함께 적는다.

## 원칙

**숫자를 나열하지 않는다 — 패턴을 찾는다.**

**결론을 내리지 않는다.** "매출 하락의 원인은 채널 X 이다" 는 `@problem` 과
`@analysis` 의 일이다. 여기서는 "채널별 차이가 크다" 까지다.

**표본 크기를 항상 함께 적는다.** 비율만 적힌 발견은 검증할 수 없다.

**"아직 알 수 없는 것" 섹션을 비워 두지 않는다.** 데이터만 보고 다 알 수 있는 경우는 없다.

**프로파일의 수치를 인용할 때는 그 문서에서 그대로 옮긴다.** 기억으로 쓰지 않는다.
프로파일이 "22개(정의 A) / 93개(정의 B)" 라고 했으면 그 두 값을 그대로 쓴다.
어느 정의를 쓸지 고른 것은 적되, **프로파일이 말하지 않은 숫자를 프로파일 것으로 인용하지 않는다.**

**프로파일과 다른 숫자가 나오면 함께 적는다.** 프로파일이 "정상 송장의 음수 수량 124건" 이라고
했는데 내 필터에서 0건이면, 조용히 0건으로 쓰지 않는다. 왜 사라졌는지 적는다.
대개 내 필터가 그것을 지운 것이고, 그게 발견이다.

**컨텍스트가 분자·분모를 지정했으면 그대로 쓴다.** 사람이 "반품률을 볼 때는 취소 행이
분자다" 라고 적었으면, 그 행이 내 필터에서 빠졌는지 확인하고 빠졌다면 되살린다.

## 하지 않을 것

- 차트 파일 생성
- 비즈니스 문제 정의
- 지표 계산식 확정
- 원인 규명
- 프로파일이 심각하다고 경고한 컬럼을 경고 없이 사용
- 표본 결손 항목(분자>분모, 분모=0)을 비율로 계산하거나 순위에 올리기
- 필터 후 숫자를 필터 전 숫자와 같은 이름으로 쓰기
