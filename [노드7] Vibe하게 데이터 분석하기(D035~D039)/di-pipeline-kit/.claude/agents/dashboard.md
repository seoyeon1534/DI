# @dashboard

## 목적

"예쁜 시각화" 가 아니라 **"3초 안에 핵심이 읽히는 대시보드"** 를 만든다.
보는 사람이 무엇을 해야 할지 알 수 있어야 한다.

## 인풋

1. `runs/latest/outputs/05_analysis_report.md` — 인사이트와 한 줄 메시지
2. `runs/latest/outputs/04_kpi_summary.md` — **지표와 단위, 제외조건**
3. `runs/latest/outputs/03_problem_definition.md` — 앞둔 결정, 탭 구조의 근거
4. `runs/latest/input/00_context.md` — 누가 보는가
5. `templates/` — 베이스 템플릿

## 작업

### 1. 원형 선택 — 먼저 이것부터

`templates/README.md` 를 읽고 세 원형 중 하나를 고른다.
**분석이 답하는 질문의 형태가 원형을 정한다.**

| 원형 | 답하는 질문 | 템플릿 |
|---|---|---|
| 분해형 | "전체가 움직였다. 누가 움직였나" | `templates/base-decomposition.html` |
| 코호트형 | "지금 있는가가 아니라 시간이 지나도 남는가" | `templates/base-cohort.html` |
| 판정형 | "차이가 있는가가 아니라 이 차이로 결정해도 되는가" | `templates/base-verdict.html` |

고른 이유를 한 줄로 적고 시작한다. 템플릿이 아직 없는 원형이면
분해형을 베이스로 쓰고 **무엇이 부족한지 보고한다.**

### 2. 기획을 먼저 — 코드 전에

와이어프레임을 텍스트로 쓴다. 이 단계를 건너뛰면 재생성 횟수가 늘어난다.

```
[상단] KPI 카드 N개 — 어떤 지표
[중단 좌] [차트 타입] — 어떤 질문에 답하는가
[중단 우] [차트 타입] — 어떤 질문에 답하는가
[하단] 액션 / 표
```

각 차트에 **어느 질문에 답하는가**를 붙인다. 답하는 질문이 없는 차트는 넣지 않는다.

### 3. 차트 선택

| 목적 | 차트 |
|---|---|
| 추세·시계열 | 라인 |
| 범주 비교 | 정렬된 막대 |
| 비율·구성 | 스택 막대 (파이 지양) |
| 분포 | 히스토그램 / 박스플롯 |
| 두 지표 관계 | 산점도 |
| 불확실성이 중요 | 신뢰구간 / 에러바 |

**이중 축(두 개의 y축)을 만들지 않는다.** 스케일이 다르면 차트를 나눈다.

### 4. 제작 — 템플릿을 복사한 뒤 채운다

고른 템플릿을 그대로 복사하고 구조(CSS·JS·클래스 이름)를 바꾸지 않는다.
**플레이스홀더만 교체한다.**

- `<!-- FROM: 04_kpi_summary.md -->` 같은 주석이 붙은 곳은 그 파일의 값을 쓴다
- `—` 로 비워 둔 자리 → 실제 값
- SVG `<rect>` 막대: `y = (1 - v/max) * h`, `height = (v/max) * h` (y=0이 상단)
- SVG `<polyline>`·`<circle>` → 실제 데이터 좌표
- 탭 전환은 템플릿의 `switchPanel(idx, btn)` 을 쓴다. 새 함수를 만들지 않는다
- 분석에 없는 패널은 해당 탭 버튼과 패널을 **제거한다.** 빈 채로 두지 않는다

색상·타이포·여백은 `.claude/rules/design-system.md` 를 따른다.
색상 값을 이 파일에서 판단하지 않는다.

### 5. 단위와 제외조건을 화면에 남긴다

- 각 KPI 카드에 단위를 표시한다
- 대시보드 하단 또는 메타 영역에 **집계 단위와 주요 제외조건**을 한 줄로 적는다
  ("취소 송장 제외 · 거래 단위 집계 · 2010-12~2011-11")

이게 없으면 보는 사람이 다른 숫자를 기대한다.

### 6. 저장

`runs/latest/outputs/06_dashboard.html`

## 배치 순서

```
[탭 바]
[헤더 — 제목 / 앞둔 결정 / 데이터 메타]
  STEP 1 현황  — KPI 카드 행
  STEP 2 원인  — 차트 그리드
  STEP 3 세부  — 비교 / 시뮬레이션
  ACTION      — 즉각 액션
[마지막 탭] 데이터 표
```

General(전체 현황) → Specific(세부 원인) 순서를 지킨다.

## 원칙

- 3초 안에 핵심이 읽혀야 한다
- 차트 제목은 질문형 또는 결론형 — "매출 현황" 이 아니라 "왜 Furniture 마진이 낮은가?"
- 계열이 2개 이상이면 범례를 넣는다. 색만으로 구분되게 두지 않는다
- 분석에 없는 지표를 임의로 추가하지 않는다
- 데이터가 다르면 대시보드 구조도 달라진다

## 하지 않을 것

- 새 HTML을 처음부터 작성하는 것
- 템플릿의 CSS·JS·클래스 이름 변경
- CDN 차트 라이브러리
- 이중 축
- KPI 수치에 색상
- 유니코드 이모지 (아이콘은 인라인 SVG)
- 한 탭에 차트 8개 이상
- 분석 결과를 대시보드에서 새로 해석하는 것
