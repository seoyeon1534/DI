# 지표 정의 규칙

`@metrics` 와 `@analysis` 가 공유합니다. 지표를 문서에 적는 모든 곳에 적용됩니다.

## 지표 하나는 네 가지가 다 있어야 한다

| 요소 | 없으면 생기는 일 |
|---|---|
| **이름** | — |
| **계산식** | "전환율" 이 사람마다 다른 숫자가 된다 |
| **단위** | %, %p, 원, 건, 명 — 3%와 3%p를 섞는다 |
| **제외조건** | 표본이 조용히 달라진다. 같은 계산식으로 다른 값이 나온다 |

**네 번째가 가장 자주 빠지고 가장 비싸다.**

## 제외조건에 적을 것

계산에서 **빼기로 한 행**과 그 이유를 적는다. 빼지 않기로 한 것도 적는다.

```markdown
- 제외: 취소 송장(Invoice 가 C 로 시작) 1,842행 — 매출 집계를 왜곡
- 제외: 단가 0 이하 213행 — 사은품인지 오류인지 불명. 확인 필요로 넘김
- 유지: 고객 ID 결측 9,102행 — 매출 집계에는 영향 없음. 단, 고객 단위 지표에서는 제외
```

같은 데이터에서 지표마다 제외조건이 다를 수 있다. 지표별로 적는다.

## 계산식은 실제 컬럼명으로 쓴다

```
나쁨   전환율 = 전환수 / 방문수
좋음   전환율 = SUM(conversions) / COUNT(DISTINCT session_id)
```

컬럼명을 쓰면 그 컬럼이 없을 때 바로 드러난다. 추상적으로 쓰면 없는 데이터를 가정한 지표가 남는다.

## 분모를 먼저 정한다

비율 지표는 분자보다 분모가 어렵다. 분모를 정할 때 확인할 것.

- 어느 집계 단위인가 — 행 / 수량 / 거래 / 고객 / 세션
- 제외조건이 분모에도 적용되는가
- 분모가 0이 되는 경우가 있는가
- **분자가 분모를 넘을 수 있는가.** 넘는 항목이 있으면 표본 결손이다
  (analysis-principles.md 「표본이 이 질문에 답할 수 있는가」)

**집계 단위를 지표 이름에 넣는다.** 같은 이름으로 두 단위를 쓰면 반드시 표류한다.

```
나쁨   반품률
좋음   반품률(수량 기준) = 반품 수량 / (판매 수량 + 반품 수량)
좋음   반품률(행 기준)   = 반품 행 수 / (판매 행 수 + 반품 행 수)
```

두 값은 다르다. 어느 쪽으로 정했으면 하류가 다시 정하지 않는다.

## 집단을 정의하면 개수를 고정한다

"저매출·고반품 상품" 처럼 **조건으로 만든 집단**은 이름과 개수를 함께 못 박는다.

```markdown
- 집단: 저매출·고반품 상품 = 매출 < £74(중위수) AND 반품률(수량 기준) >= 10%
- 개수: 42개 · 매출 합 £1,637.07
- 제외: 표본 결손 7개 · n<30 26개 → 권고 목록에는 9개만 올린다
```

하류 단계가 이 집단을 다시 계산해 **개수가 다르면 반드시 보고한다.**
같은 이름으로 42개·53개·39개가 돌아다니면 그 뒤의 모든 권고가 무엇에 대한 권고인지 알 수 없다.

## 이 지표가 속일 수 있는 경우

각 지표에 한 줄을 붙인다. **개선 없이도 이 지표가 좋아지는 방법**이 있는가.

```markdown
- 속일 수 있는 경우: 저효율 채널을 집행 중단하면 평균 ROAS는 오르지만 총 매출은 줄어든다
- 속일 수 있는 경우: 기준일을 요청일에서 확약일로 바꾸면 정시율이 저절로 오른다
- 속일 수 있는 경우: 분모에서 신규 고객을 빼면 유지율이 올라간다
```

이 칸을 채울 수 없는 지표는 대개 정의가 덜 된 지표다.

## 선행 지표와 결과 지표

- 결과 지표만 있으면 문제를 너무 늦게 안다. **선행 지표를 최소 하나 포함한다**
- 두 지표가 어떤 순서로 움직이는지 함께 적는다
